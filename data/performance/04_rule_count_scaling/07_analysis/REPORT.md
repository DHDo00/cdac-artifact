- 所有 N>0 的配对差值中位数落在 ±3.4ms 内，且每个规模的中位数符号在两 boot

  “S2 对 S3（单条不命中规则）未分辨”一致，并扩展到 128 条规模。

## 3. 解释口径（固定）
- N=0 是**同一 CDAC 制品上的空规则参考**，不是“无 CDAC”基线（round-11 的
  S0 才是跨制品无 CDAC 基线）。
- T(N)−T(0) 是**端到端**（Binder 调用 + provider 写路径 + 执法扫描 + PFD 返回）
  差值，不是纯内核查询耗时。
- 不与 round-12 旧制品差值拼接计算总开销。
- 拒绝路径（T1/POS）单独报告（正确性结果），不与允许请求直接相减解释为拒止开销。
- bootstrap 只描述当前采样条件的区组级不确定性；不把每请求当独立启动样本。

## 4. 诊断（LOG_ON，单独，不混入主采样）
- kernel `perf … decision_ns`（iguard_apply_file_open_decision 内部耗时，
  含 8192 槽全表扫描）：各规模样本均在 ~20µs–4ms 区间、且有 34ms 量级离群
  （LOG_ON 自身的打印/调度噪声），未见随 N=0→128 的单调增长。该诊断仅作解释，
  不为本轮新增内核计时探针（复用既有 perf 行）。
- LOG_ON 下 A→X 拒止文本行（N=1 与 N=128）：
  `real-enforce seq=… caller_uid=10122 caller_pid=3671 service_id=5 op_id=401
  service=external_storage_provider_open_ op=openAssetFile path_tail=X.bin
  errno=-13 verdict=deny-now`——真实执法依据文本证据，两个端点规模一致。

## 5. 与实现审计的对应
- 执法查找恒遍历 8192 槽（无索引、无提前返回），但 128 个 used 槽仅占总槽数
  1.6%，且未命中槽仅 `if(!used) continue`；每条深失败填充规则只增加若干次字段
  比较与 2 次 strcmp，预期边际成本为亚微秒级。端到端中位数噪声（本会话约 ±2ms
  区组级）无法分辨该量级，符合观测。
- 128 规模时填充规则全部进入执法全表扫描；只有前 63 条填充 + 目标规则进入 64
  项 fd 血统缓存（该缓存不参与裁决）。见 00_implementation_audit §5。
- 本会话绝对延迟（中位数 ~15.5–17.3ms）高于 round-11 配对运行的 S2/S3
  （~5.3–6.7ms），属跨会话/宿主条件差异；主指标用同区组 N=0 配对抵消水平差，
  但更高的噪声下限进一步降低可分辨的最小效应。min（3.5–4.5ms）与 round-11 S0
  量级一致，说明分布存在重尾而非整体偏移。

## 6. 限制
- 仅 2 个独立 boot、每 boot 20 区组、每区组 5 条记录行；无正式置信区间
  （仅区组级 bootstrap 作为参考）；跨 boot 一致性只有 2 个样本。
- 单一路线（ESP 5/401 写）、单文件、单授权、单 APK、LOG_OFF 固定；framework
  quiet 属性沿用 round-11 已核实的既有行为。
- 合成填充规则（synthetic workload）只覆盖“字段逐层失败至 ino”的单条求值路径，
  不宣称经过真实业务审查；未测 8192 容量上限本身。
- 不按延迟删除样本；无干扰块、无失败配置（disturbed=0、invalid=0）；无效行
  在分析中为 0。
